# RAG 检索原型（实验）

> 这是一个**独立实验目录**：不改动现有网站、导入器、正式 JSON 和图谱，也不连服务器数据库。
> 目的是给「用户描述需求 → 检索候选 API → 推荐并说明差异」这条链路补上缺失的**检索层**。

## 为什么要做这个

`docs/project-goal.md` 已经指出：`app.py` 的 `/api/chat` 是「先生成回答，再顺手执行一次 Cypher」，
结果不回给模型，查询限制只写在提示词里，没有形成"检索结果支撑回答"的闭环。

本目录提供闭环里缺失的那一环：**一段中文需求文本 → 排序好的候选 API 列表（带分数、模块、since）**。

## 结论摘要（20 题测试集，同一批 15 题对比）

| 配置 | Recall@1 | Recall@3 | Recall@5 | Recall@10 | MRR |
|---|---|---|---|---|---|
| ① 基线：英文 BM25，不做中文处理 | 7% | 13% | 20% | 20% | 0.113 |
| **② 本目录检索器（版本化语料）** | **40%** | **73%** | **87%** | **100%** | **0.594** |
| ③ 参考：同一检索器跑完整语料 `03_extracted_json/API/` | 47% | 73% | 87% | 93% | 0.622 |

全部 17 道可答题口径下，② 为 R@1=47% / R@3=76% / R@5=88% / R@10=100% / MRR=0.642。

**弃答判定 20/20 全对**：3 道"本来就没有答案"的题（微信支付、AR 测距、API6.0 剪贴板）
全部正确回复"检索不足"，其余 17 题没有误弃。对应项目目标里"无证据不编造 API"的要求。

原始输出见 `results/`。

## 关于要不要上向量库：建议不上

实测语料体积：

| 内容 | 体积 |
|---|---|
| 一个版本的域入口清单（API6.0，2,857 条含描述） | ≈ 80k tokens |
| 四个版本的域入口清单（9,336 条） | ≈ 240k tokens |
| 一个版本的全部节点（18,289 条） | ≈ 557k tokens |
| 四个版本全部节点（60,033 条） | ≈ 18M tokens |

这类语料是**结构化、短、具名**的；用户要的答案是一个**标识符**；而且带着**版本这种硬过滤条件**。
这是"在可枚举实体里找工具"，不是"在长文档里找语义片段"，向量检索的强项在这里用不上。

建议按 9.27 会议决议走：**把知识图谱封装成 agent 可调的结构化查询工具**。

```
list_kits(version)                → 该版本有哪些 kit / 模块
list_apis(version, module)        → 该模块下可推荐的 API 清单
get_api(version, name)            → 完整字段：参数、返回、since、syscap、错误码
search_apis(version, keywords)    → 关键词检索      ← 本目录已实现
check_coverage(version, domain)   → 该域在本版本有没有数据  ← 本目录已实现
diff_api(name, v_old, v_new)      → 跨版本差异
```

再配一份单版本的域入口目录（约 80k tokens，可整体放进上下文），模型就能
「先看目录选域 → 调 `get_api` 拿真实字段 → 基于字段做推荐和对比」。

## 用法

依赖：仅 Python 标准库。

```bash
# 1. 建语料（只读 03_extracted_json/，输出到 data/，不入库）
python build_corpus.py

# 2. 单条查询
python retrieve.py "怎么发起一个 HTTP 请求"

# 3. 跑测试集
python evaluate.py            # 召回率
python eval_gate.py           # 弃答判定
python final_compare.py       # 三个配置的公平对比
```

## 文件

| 文件 | 作用 |
|---|---|
| `build_corpus.py` | 把 JSON 摊平成检索语料，并生成 `data/file_inventory.json`（文件 × 版本 → 可用节点数） |
| `retrieve.py` | BM25F 检索、中文受控词表、类型/族入口先验、两层弃答判定 |
| `testset.json` | 20 题模拟提问 + 标准答案（每条答案都用脚本核实存在于语料） |
| `evaluate.py` | 跑测试集算 Recall@k / MRR，并打印失败位次 |
| `eval_gate.py` | 评估"该不该弃答" |
| `final_compare.py` | 三个配置在同一批题上的对比 |
| `results/` | 上述脚本的实测输出 |

## 检索器做对了什么

| # | 改进 | 原因 |
|---|---|---|
| 1 | 中文 → 英文受控词表（约 90 条） | 语料 99% 是英文描述，中文需求字面匹配不上 |
| 2 | 前缀归一（取前 5 字符）代替词干化 | `vibration` / `vibrator` / `vibrate` 需归一到同一个 key；后缀词干化会把它们切岔 |
| 3 | BM25F 分字段打分 | 文件名权重 5、API 名权重 6、描述 1.2；`name`/`file` 用二元命中，避免同一词重复出现被放大 |
| 4 | 族入口先验 | `@ohos.notificationManager` 里的 `namespace notificationManager` 加 35% —— 它才是该域入口 |
| 5 | 两层弃答 | ①前 5 候选都没在 API 名/文件名级命中查询词 ②查询域在目标版本是空文件 |

第 5 条的第 ② 种是关键：纯分数阈值分不开。例如「API6.0 怎么用剪贴板」的 top1 分数 9.54，
比可答题的最低分 5.84 还高，因为候选叫 `TextArea.onCopy`，名字里就有 copy。
必须靠"该域在本版本是不是空的"来判断。

## 未验证 / 已知限制

- **没有在服务器数据库或部署网站上验证过。** 本原型读本地 `03_extracted_json/`，
  不下发任何 Cypher，未连接过 Neo4j。服务器 `:7687` 从外部不可达，`:5000` 的只读接口可用。
  **合并前建议在隔离测试实例上复核。**
- 中文词表是人工受控词表，覆盖有限，是当前召回的主要瓶颈。
- 测试集 20 题由一人标注，未经过第二人复核。
- 未实现 9.27 会议提出的三类依赖关系（类型依赖 / 调用依赖 / 演化依赖）。
- 只做召回，不做 rerank 和生成。把 R@3=73% 变成可交付推荐，还需要模型重排那一层。

## 数据侧观察（与检索器无关，但直接影响推荐质量）

1. **四个版本目录是"解析前缀"。** 解析器遇到不认识的语法即中止，只保留中止前的声明。
   例：`@ohos.router` 在 API6.0 里只剩 `namespace router` + `RouterMode` 枚举，`pushUrl` 全无。
   在 API6.0 全量数据里搜 `pushUrl` 零命中，所以不是挪到了别的文件。

   | 文件 | API4.1 | 5.0 | 5.1 | 6.0 | `API/` 目录 |
   |---|---|---|---|---|---|
   | `@ohos.notificationManager` | 6 | 6 | 6 | **0** | 89 |
   | `@ohos.data.relationalStore` | 8 | 8 | 8 | **0** | 374 |
   | `@ohos.pasteboard` | 33 | 41 | 41 | **0** | 127 |
   | `@ohos.multimedia.camera` | 7 | 7 | 7 | 7 | 517 |

2. **空的 `.d.ts` 文件比例**（`build_corpus.py` 会重新输出这张表）：

   | 版本 | 文件数 | 0 可用节点 | 占比 |
   |---|---|---|---|
   | API4.1 | 666 | 274 | 41% |
   | API5.0 | 817 | 30 | 4% |
   | API5.1 | 834 | 30 | 4% |
   | API6.0 | 865 | 85 | 10% |

3. **图谱比源码少了三类字段。** `_run_import.py` 映射了
   `name/type/description/comments/since/syscap/parent_name/module/level`，
   但没有映射 `parameters`、`return_description`、`error_codes`
   —— 而这三类恰好是"说明怎么调用"必需的。源码 JSON 里这三类是有的。

4. **`03_extracted_json/API/` 是唯一接近完整的语料**（26,735 条），但：
   - 来源未记录（`docs/data-contract.md` 已标"来源待确认"）
   - `sdk_version` 标为 `API`，已在线上图谱里形成第五个版本
   - `ets/` 与 `js/` 子目录内容相同（617/621 个文件字节一致），是重复
   - `since_version` 最高为 23（API6.0 为 20），比 API6.0 更新
