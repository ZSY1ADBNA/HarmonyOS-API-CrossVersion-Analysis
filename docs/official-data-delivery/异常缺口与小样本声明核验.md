# 异常缺口与小样本声明核验

2026-10-13。本批落实计划第1、2步：核查4.1 Button表格异常、五处声明缺口，并对照channelLayout、volumeMode、minFontScale等小样本。这里的“声明”是源码中正式列出名称、类型及参数的条目；SDK是开发工具包。本批核对的是官方源码仓库中的声明，实际发布的SDK包、工程编译和团队系统联调仍未完成。

## 已完成：查清并修正一条错误表格行

固定4.1文档第66行在三列表头下写了四列，首列为value。简化模型：

```text
表头：名称 | 参数类型 | 描述
原行：value | Length | 是 | 文本显示字号……
```

此前不能猜它代表fontSize。本轮取得三份相互对应的证据：

1. [修改前原文](https://github.com/openharmony/docs/blob/f2345b138f205c8cdf37a8885dabd7abe1596c9c/zh-cn/application-dev/reference/apis-arkui/arkui-ts/ts-basic-components-button.md)：原本是fontSize、Length、字号说明的三列属性行。
2. [2027c65修改差异](https://github.com/openharmony/docs/commit/2027c65cf14cc88cb8bbb5a10df68aec31e6f776)：该行被替换为value、Length、是、字号说明四列，替换关系可直接核对。
3. [同发行声明第858行](https://github.com/openharmony/interface_sdk-js/blob/7a77f758ee14c7288b9c7fbc9c39ccc072544565/api/%40internal/component/ets/button.d.ts#L858)：fontSize(value: Length): ButtonAttribute。

因此，已在新的独立候选批次中将这条记录识别为Button.fontSize，保存最新原文中的字号说明和默认值。它像是给错贴标签的栏目重新确认名称；不是把value批量改名。原件及原错误行都保留，记录附有修正规则、修改提交、父提交及声明来源。

规则只接受精确的4.1文档指纹、第66行内容、修改前文件指纹、差异和同发行声明。原文、历史或SDK声明不符时拒绝修正。文档没有字段级起始版本标签，仍保存为未知；源码的7/9/10/11多组注释另存，不冒充文档直接声明。

## 已核对：五处缺口的含义

完整搜索4.1、5.0.3、5.1.0固定中文Markdown范围，共18,794份文档，逐文件SHA256及Git blob指纹一致，无解码遗漏。同时读取各发行Button及音频源码声明，并为一个同名问题补读5.0.3的Text声明。没有用新发行内容填旧发行。

- 4.1 Button.minFontScale：中文范围没有匹配，ButtonAttribute自身没有声明。
- 5.0.3 Button.minFontScale：ButtonAttribute自身没有声明；搜索找到6处同名提及，但声明属于Text，其他是例子或引用。5.0.3 TextAttribute.minFontScale的源码声明核对通过，属于文本组件，不能挂到Button上。
- 4.1、5.0.3、5.1.0 AudioVolumeMode：中文范围没有匹配；选定音频声明文件没有该枚举，AudioRendererInfo自身也没有volumeMode属性。

目前四项记为“固定源码目标类型中未声明”，另一项记为“同名属于Text，非Button”。这已解释代表页缺口，但不能扩大成“任何SDK包中绝对不存在”。尚未验证生成后的SDK、继承成员和所有语言变体。

在本次五发行样本中，Button.minFontScale从5.1.0源码/文档中找到，标注18；AudioVolumeMode及volumeMode从6.0样本中找到，标注19。这是样本范围内的对应关系，不把API级别18/19当成系统发行名称。

## 已完成：小样本源码与文档对照

核对11份源码声明文件，选出18条来源声明；形成11条独立文档候选，其中1条为修正后的fontSize。channelLayout、volumeMode、minFontScale共10个发行/字段组合逐项检查名称、归属、类型、可选性、版本及明确系统能力，全部匹配。源码字段自己的能力与文档父级能力分别保存，不覆盖原证据。

6.1的channelLayout同时出现11、12 dynamic、23 static版本注释；volumeMode出现19 dynamic、23 static。dynamic/static分别表示注释中区分的动态/静态语言适用标记，本批保留完整原文，不自行归成单一版本门槛。多组注释还可能区分卡片、跨平台或原子化服务范围，尚未展开成完整适用条件模型。

检查这些声明及其祖先的systemapi/internal限制标签，保留源码层面的检查结果；没有限制标签不等于已确认发布SDK公开范围。所有候选的sdk_public_status仍为not_verified。
