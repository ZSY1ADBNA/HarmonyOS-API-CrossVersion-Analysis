# 两个样本接入规则与隔离演练

批次YU-BRIDGE-20261014，2026-10-14。执行与自查完成，待成员验收。范围是既有两个OpenHarmony 4.1/API11样本的接入演练，未执行共享迁移。

## 为什么先做这一步

总体计划1.0明确设备根因诊断、自动改代码和编译运行验证不属于第一版查询交付；已经完成的编译属于额外样本证据，设备运行可以后续增加。步骤04要求先完成小样本身份、重复导入、版本隔离和逐项对账，再分批扩大。其他发行的小样本证据应接着补，跨版本回答需要两边来源；不需要等待全部发行和全部Kit完成才接文档检索与回答评测。

当前先验证接入规则及失败保留原图，再补第二发行同领域的正式SDK样本。共享迁移在映射规则确认、实际部署提交/数据基线核对、小范围发布与回滚方式明确之后开展；本批保持已有“不写共享/生产环境”范围。设备能力、设备上的权限与真实运行行为在具备相应设备和运行条件后单独验证。

## 接入规则

影子记录是与旧记录分开保存的新记录，保留旧数据供对账和回退。仅演练这种增量方式，不覆盖旧UID、不改旧节点或关系。fontSize在固定Button JSON中缺声明，因此新增独立记录；channelLayout已有旧字段，因此新增完整记录并单独关联旧记录作为证据。LEGACY_RECORD_EVIDENCE只表示旧数据映射依据，不表示两个API跨版本等价，也不是调用关系。

所属类型、成员类别、版本、类型、已有模块、完整签名和可选性有冲突即拒绝；同名同所属类型重复出现也拒绝。旧模块未知/完整签名与可选性未保存，只能依据已核验的正式声明补到新记录。原旧字段不就地补写。写入前再比对旧记录完整内容指纹及现有已核验候选，避免直接应用过时映射。

候选身份仍为本批局部编码，团队全局身份设计尚未确认。本工具只有固定本机独立实例连接和演练标签，没有共享目标参数，不能作为共享库迁移入口。

## 真实验证

tools/rehearse_sample_bridge.py重新核验两个原文/SDK声明、编译产物及固定旧JSON，生成两条接入动作。独立Neo4j 5.26.32真实执行三个事务场景：成功且重复应用、首个影子记录写入后主动抛错、旧记录被构造修改后拒绝。

11项检查通过：演练中3个临时节点（两个完整影子及一个旧audio副本），重复应用数量不变，完整签名和可选性保留，旧副本正文不变，旧记录证据关系恰好1条，中途写入失败和旧基线变化均被检查。每个场景均显式回滚，结束后全图节点属性、标签和关系的指纹与原图一致。没有提交任何探针数据或更改现有候选。

4项针对性回归通过，覆盖8种字段冲突、重复匹配、错误发行、原件保留及缺失状态区分。最终规则加固后真实重跑仍通过。证据见sample-bridge-verification.json。

## 异常与限制

- 首轮查询尚未存在的DeliveryBridgeProbe标签收到UnknownLabelWarning：这是Neo4j提示没有该演练类别，返回0符合预期；真实事务演练后再次运行无该提示。没有以忽略错误代替检查。
- 复查发现同名而所属类型不符可能被当作缺失，已改为拒收并加入回归，实际重跑通过。
- “旧基线变化”是单个事务内构造的变化，验证写入前检查及回滚，不代表两个客户端同时修改的并发测试。团队共享部署、持久增量发布和已提交变更的回退仍未验证。
- 本轮只检查接入规则与独立数据库，未执行设备运行、其他发行正式SDK验证或网页交互复测。既有原件、候选UID、网页及共享导入入口保留。
