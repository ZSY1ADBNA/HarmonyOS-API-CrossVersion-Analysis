# 版本追问与条件澄清核心

2026-10-15执行与自查完成；本批仅为本地会话核心，尚未接HTTP或网页，负责人/验收人待确认。

新增verified_query_session.py。最小上下文只保存上一条需求及明确版本，不保存候选或证据缓存；每次有效查询重新核对现有四条声明及指纹。支持先问功能再补版本、先选版本再问功能、明确切版本、比较方向反转、换话题与条件追问。新话题未命中不会恢复旧API，未知发行清除版本并请求澄清；默认值、权限、设备及直接替换问题只返回已核验声明和明确证据缺口。

回归实际发现并修复三个状态问题：

- Unicode的词边界把中文当标识符，漏识“4.1和5.0.3”的第二个版本；改用ASCII标识符边界，同时不把项目API5.0标签当正式发行。
- 显式清空版本原本可能继承旧版本；现在返回缺版本，不能复用旧候选。
- 比较方向尚未补齐时，单独补一个版本原本可能降为单版本查询；现在继续澄清目标，待两端明确才比较。已明确的待补目标会保留，普通切版本则清除旧比较目标。

状态字段严格限定，拒绝system角色、候选注入、未知版本、超长需求及非法Schema；不修改调用方状态对象。范围仅含4.1/API11和5.0.3/API15的fontSize/channelLayout，不声称通用自然语言理解。

40项相关Python回归通过。实际以6组、17轮本地证据查询跑通缺版本补齐、版本切换、反向比较、未知版本、换话题、条件缺证据和比较方向澄清；每轮预期/实际状态及最小上下文见verified-session-verification.json。证据输入指纹未变，未调用模型/HTTP/浏览器，不写数据库。
