## 来源与缓存

使用既有 sources.json 中各仓库独立固定的完整提交。正式发行标签解析出的提交必须与锁匹配，远端标签变化时停止该来源并保留锁。旧目录清单只有提交相同时才能复用；前三发行维护分支清单不能替代正式标签清单。历史 6.0.0.1 Release、6.1 LTS 原件继续保持身份。

原始包、Git对象缓存、逐文件正文、文件清单、结构化正文和数据库都在忽略的 data/delivery；普通 Git 只交付工具、来源锁和小报告。归档从官方仓库的固定提交重建，archive_transport=git_archive 时，archive_url 表示对应官方快照入口，不表示归档字节与 GitHub codeload 压缩包相同。Git归档禁用自动换行转换；记录本地归档 SHA256，逐文件另验 Git blob SHA 与固定提交目录相同。

files.jsonl 保存路径、大小、SHA256、Git blob SHA与状态；inventory.json 单独记录固定提交的目录完整性。普通文件按Git blob SHA核验。文档附件采用Git LFS时，Git目录记录的是指针，归档可包含展开的原件：先验指针Git SHA，再按指针声明的SHA256和大小核验附件；同时保存lfs_pointer_text、payload_git_blob_sha与实际文件SHA256。仅剩指针、缺子模块或未物化链接时保留缺口，不能当完整正文。正文完成状态以来源清单和覆盖对账为准，不能以 ZIP 有效、部分解压、README 数量或目录清单代替。

许可按各来源根许可及嵌套许可文件逐项保存指纹。已读取的4.1示例根LICENSE区分测试材料协议与其他材料的Apache许可，不统一把全部测试材料标为Apache；发布或分发时需保留对应原文，当前不把上游完整原件上传到普通Git。

## 重建与自查

从仓库根运行，Python 3.12.5、Git 2.55.0.windows.5 实测；无需数据库连接或真实凭据。

```powershell
python tools/collect_official_sources.py --lock docs/official-data-delivery/yu-source-lock.json --kinds docs samples --transport git-batches --workers 3
python tools/scan_official_materials.py
python tools/test_material_collection.py -v
```

重建本轮输入必须传入已发布的yu-source-lock.json；新数据根从该锁导入完整提交，不重新把可变ref当成本轮输入。既有根与锁不同则拒绝覆盖，另选--root。不传锁只用于重新核对并建立新的来源批次。采集器支持 --releases 指定准确 release_id 续跑，例如 OpenHarmony-4.1-Release。git-batches先固定目录、按文件对象分批取得，并复用相同内容；已验证ZIP保存完整正文，body_storage=verified_archive时不重复解压。扫描器直接读取归档，文件清单独立保存。网络失败不改变固定提交，也不使用master补缺。失败来源不进入正文扫描，未取得者在扫描报告中显式列出。

扫描遍历全部已取得文档/示例文件，复核文件指纹。中文 Markdown 按参考、指南、设备开发、发行等路径类别保留完整正文、标题与行号；正文不依赖二级标题存在，围栏内标题不当目录。相对链接未在取得范围中发现时列入复查，不能直接断定上游断链，HTML链接与锚点尚未核验。

示例工程候选根依据构建配置与入口文件，模块层次仍需语义核对，数量不能当应用数量。源码扫描仅输出带文件/行号的@ohos、@kit词法导入候选，不确认重载、调用关系、设备支持或运行顺序。配置JSON5、权限、设备类型、SDK条件、C/NDK与API语义关联待专门处理；未编译的工程保持build_verified=false。
