# 自动化提取程序缺陷检查与修复

2026-10-12，范围为本任务的官方资料采集、专用语义适配与独立检索脚本。

当前 Python 程序读取固定提交的 OpenHarmony 官方文档归档，保留原文和来源证据，再由 AudioRenderer、AudioCapturer、Button/fontSize、AVErrCode 专用适配器提取候选字段。不是自动编译程序，也未完成全部 Kit 的语义提取。

## 已复现和修复

1. 代码围栏内的签名、参数表、版本标签可能被当成声明。现在统一过滤围栏，仍完整保存原文；带语言后缀的围栏标记不能关闭已有围栏。
2. 顶层接口标题使归属范围过宽，可能将后面的另一个接口成员归给 AudioRenderer。现在根据真实标题祖先中最近的接口容器判断；围栏内伪造标题无效。未知适配器明确报错。
3. 数据库与候选 JSONL 分两步替换，第二步写入失败可能造成批次不一致。现在先写独立批次目录，完成后只原子更新 current.json；默认检索核对两个文件的路径与 SHA256，失败继续保留上一批。旧文件保留作为历史产物；显式 --database 查询指定数据库。
4. 导入的来源锁只在缓存复用时检查预期归档指纹和文件数，完整采集路径遗漏检查。现在完整采集也强制检查，失败不能生成成功收据。
5. 符号链接未物化却可能报告正文完整。现在记录目标原始字节、指纹和文件数，并明确报告未解决依赖，不创建本地链接。
6. 扫描缓存收据缺少输出指纹时可能被信任。现在必须包含四个输出文件指纹，并核对收据与来源归档 SHA256 一致。
7. 中文与英文混合检索会静默丢弃中文约束。当前仅支持英文技术标识符，遇到不支持的中文明确报错；检索上限拒绝布尔值与浮点数。
8. 原子 JSON 写入使用固定临时文件名，有并发碰撞风险。改为每次独立临时文件。

## 实际验证

- 45 项测试全部通过，含新增的 8 项缺陷回归；失败发布注入后，当前批次清单和上一批内容保持不变。另有此前的失败批次不替换数据库回归。
- 五发行实际重提取：20 次适配、17 份独立原文、1269 条候选，与修复前计数一致；40 项批次检查全部通过，零表格警告。
- 现有 1269 条记录的声明行审计没有落在代码围栏内。围栏和归属缺陷通过构造输入复现，不能据此声称此前真实样本已受污染。

以上不代表全部文档无缺陷或全量语义正确。正式 API 身份、SDK 配套、示例编译、共享库接入、全 Kit 覆盖和成员验收仍未完成。
