# 03 提取修复与检查

任务量：高。建议 1 人实施和检查。依赖：步骤 01 的样本与版本；步骤 02 提供字段需求。

## 必要知识和输入

理解语法树、声明与注释的区别。interface 描述对象结构，函数是可调用声明，方法属于对象，属性描述数据。输入为固定提交的声明、历史失败样本和人工对照记录。

## 技术实现要点

1. 在样本上验证 TypeScript 编译器 API 或兼容解析器能否识别语法，记录不能解析的文件和结构。
2. 用语法树识别函数、方法、接口、类、属性、枚举、类型别名、命名空间及嵌套成员，避免以文本包含 class 等词判断类型。
3. 从语法提取完整签名、参数顺序、可选标记、返回类型及泛型；每条重载独立保留。
4. 维护所属层次，分别保存 Kit、模块入口、命名空间、直接所属对象及完整名称。未知归属不强行编造。
5. 单独解析注释，保留原文及附着位置。since、权限、系统能力、废弃等信息可能带条件，不简单取最大或最小数字当作结论。
6. 保存仓库提交、文件路径、位置与原始声明，便于逐项对账。
7. 从起步样本就保留跨版本分析所需的独立版本快照、原始与规范化签名、参数和返回类型、重载、权限、系统能力、公开/系统标记、废弃信息及官方替代说明。未出现注释不自动解释为无权限或无变化。

统一记录至少涵盖身份与版本、对象种类、结构与签名、相关类型、注释条件及来源。字段具体编码在实现前约定，未知值与空列表必须可区分。无需为了补字段引入模型猜测。

## 历史问题待复核

- HTTP 返回的相关类型和方法遗漏。
- 属性文本被误判为类。
- 可选参数或属性统一当成必填。
- 内部声明没有继承正确归属。
- 条件化 since 被当成最早支持版本。
- 完整签名及官方位置不足。

这些来自旧核查，不代表当前代码仍全部存在。

## 小范围检查与推广

逐条比较官方原文和 JSON；既看数量也看内容。分别检查重载、接口、枚举、可选成员和相关类型的完整性。解析失败必须进入报告，不能静默丢弃。

固定样本形成可重复检查：每种重载存在、可选性正确、对象种类正确、所属层次正确、来源可追溯。先对两个版本同领域的小样本完善代码，再在本步骤内增加其他结构、同版本领域和其他版本样本；每批执行回归检查，遇到特例先找通用规则，不按 API 名堆补丁。

跨版本比较先分别保证每份快照完整正确，再在步骤 04 建立对应和差异查询。提取器保存比较事实，不从方法名猜替代关系，不把语法变化直接解释成行为变化。每批记录版本、范围、失败与未知项和检查证据，已通过批次可先交给步骤 04，后续扩展无需等待步骤 06 完成。

## 产出与验收

- 修复后的提取方法、样本 JSON、人工对账和回归检查记录。
- [ ] 样本声明没有漏提取或误分类。
- [ ] 重载、参数和类型与原文对应。
- [ ] 版本注释保留条件和证据。
- [ ] 两版本快照及差异所需字段分别准确保留。
- [ ] 分批增加结构、领域和版本后，旧样本仍通过回归检查。
- [ ] 失败及未知内容有清单。

通过后的 JSON 交给步骤 04；原始声明同时支持文档定位。
