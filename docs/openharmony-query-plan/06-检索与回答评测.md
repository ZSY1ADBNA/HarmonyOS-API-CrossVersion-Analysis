# 06 检索与回答评测

任务量：中。建议 1—2 人用预先设计的问题检验。依赖：步骤 02 的参考答案、04 的查询和 05 的完整接入。

## 评测方法

先单测查询和文档检索，再测试完整回答，以便区分“没找到资料”和“资料找到但解释错”。参考答案须由官方资料核对，不能由被测助手自行生成。

逐题记录问题、环境、预期候选和要点、实际工具命中、实际回答、引用、通过状态、失败原因和复测结果。两人参与时可分别检验检索和回答，也可对争议题独立判断后复核。

## 拷问方式

- 用中文任务描述和 API 精确名称分别问同一功能。
- 改写问题，追加“哪个版本”“为什么”“官方依据在哪里”。
- 提供错误前提，例如可选一定有默认值，观察是否纠正。
- 给不存在的名称、目标版本不适用、缺设备信息或工具失败的场景。
- 指定 callback 或 Promise，检查是否完整保留对应重载。
- 让助手展开陌生参数类型，并检查属性和枚举。
- 检查引用是否支持当前结论，而非只有相似关键词。
- 对比两个版本的签名、重载、权限和废弃信息，逐项检查双端证据。
- 交换起始和目标版本，检查差异方向；只提供一端资料，检查是否诚实说明缺口。
- 追问“是否能直接替换”，检查是否区分官方替代建议与实际兼容性验证。

## 失败分类和回修

资料缺失回到 01/02/05；声明错漏回到 03；入库丢失回到 04；召回错误回到 04/05；证据存在但回答错误回到 05。修复后复测失败题及相关回归题，不用修改提示词掩盖数据缺陷。

## 验收标准

28 道候选题先筛选并完成环境和依据核对，其中 01—14 与 21—26 用于开发，15—20 与 27—28 暂留作验收。每题按参考答案检查：正确候选、版本一致、必答事实完整、引用支持、未知处理恰当；比较题另外核对版本对应、变化方向和双方证据。不能编造签名、混合版本、漏关键重载或以随机结果伪匹配。

记录通过题数及总题数，并附失败清单；不要只报一个总分。关键事实错误即该题失败。某能力资料不足时标为未覆盖，不应从分母静默删除后宣称整体通过。

- [ ] 所有题有检查结果，失败项有定位与处理。
- [ ] 第一版承诺支持的验收题通过。
- [ ] 未支持能力明确标注，关键错误已解决。
- [ ] 工具与页面结果可以复现。
- [ ] 两版本比较题通过，新增数据批次的相关问题和旧问题已回归。

产出：评测记录、问题清单、通过的单版本和跨版本演示场景与剩余限制。随步骤 03、04 的新增批次持续评测，失败回修对应环节；更新总体计划的支持清单，不再单列第 07、08 步。
