# 04 入库与查询工具

任务量：高。建议提取检查的同 1 人连续完成。依赖：字段约定后可准备实现，验收须使用步骤 03 通过的数据。

## 技术实现要点

在独立测试数据库或实例验证；运行历史导入脚本前检查是否有清库操作，不能默认使用共享库。

1. 对对象建立稳定身份，纳入平台、版本、声明所属层次、种类和完整签名等必要信息；不能只用版本、父对象和名称合并。
2. 导入前检查标识碰撞，保留同名重载和不同模块对象；不能用覆盖隐藏冲突。
3. 完整保存参数、返回信息、属性、枚举、错误码、注释条件和来源。必要时使用关联节点；编码方式以可查询和能无损恢复为准。
4. 保留所属、类型引用等实际关系；不要把类型引用当成运行时调用关系。
5. 验证重复导入不会增生重复记录或覆盖不同声明。
6. 建立跨版本对应候选，结合完整名称、所属层次、种类、签名和官方说明核实；记录双方身份、证据和确认状态，同名不自动等价。
7. 提供指定版本对的差异查询，比较新增/删除、签名、参数可选性、重载、返回类型、权限、系统能力、公开范围和废弃信息。只有声明范围核实后才能报告新增/删除；检索无匹配本身不是删除证据。

现有 EVOLVES_TO 如用于版本对应，先核实生成方法和语义。它不能当作应用调用关系、替代关系或兼容性证明。无法确认对应的候选单独返回，不强行建立确定关系。

## 最小查询能力

- 搜索：输入平台、版本、名称或功能词、对象种类及数量限制；返回候选身份、名称、签名、说明和来源。
- 详情：按身份返回独立重载、参数、返回值、相关类型和证据。
- 使用条件：返回权限、系统标记、系统能力及未知项。
- 相关类型：继续展开参数或返回值引用的接口、枚举和类型别名。
- 版本比较：输入平台、起始版本、目标版本及 API 身份或领域，返回对应状态、逐项差异、双方出处和资料缺口。起始与目标互换时，新增/删除及变化方向随之反转。

公开工具优先封装确定的参数化只读查询，不让模型生成任意数据库操作。读取权限、数量上限和超时在后端执行，不只写在提示词里。多版本时所有查询必须限定版本。

## 历史问题待复核

重载合并、同名对象冲突、结构化字段缺失、函数方法搜不到、无匹配返回随机节点。区分首页概览与搜索结果；有关键词却无匹配必须返回空结果。

## 对账和验收

先在两个版本的小样本库中修复代码并逐项对账，再随步骤 03 的通过批次扩大同版本领域和不同版本数据。每批检查身份碰撞、重复导入、版本隔离、查询和差异事实，并更新支持清单。样本工具可先交给步骤 05，批量扩展继续在本步骤完成。

对每条样本比较 JSON 和数据库的身份、签名、参数、条件及来源。数量一致不是充分证据。检查重载全保留、相关类型可追踪、特殊字符可检索、无结果不伪匹配、重复导入行为正确。

- [ ] 数据转换没有覆盖或丢失样本事实。
- [ ] API 列表与详情可准确展示，并可区分重载。
- [ ] 查询中缺失信息明确返回未知。
- [ ] 两版本独立可查，版本对应、差异方向及双方证据正确。
- [ ] 扩大数据后旧样本回归通过，各批次有对账记录。
- [ ] 写操作无法通过查询工具执行，超量和超时被限制。

产出：测试库数据、导入对账、只读查询工具和详情展示。支持步骤 05、06。
